# Project Instructions

## This repository

Node.js (ESM) client that authenticates a second Microsoft/Xbox account and joins the owner's Minecraft Bedrock Realm via **[BedrockX](https://github.com/thejfkvis/BedrockX)**, pinned by commit in `package.json`. Not `bedrock-protocol` — that library **cannot connect to this Realm at all**: the Realm has migrated to NetherNet (`NETHERNET_JSONRPC`) and `bedrock-protocol` speaks only RakNet for Realms. Read `docs/why-bedrockx.md` ("Why BedrockX and not `bedrock-protocol`") before touching the connect path. `README.md` has install, run, the gate and an index of `docs/`, which holds the per-feature reference and the hard-won protocol gotchas (`docs/gotchas.md`).

Two hosts: the Windows tower (dev) and the Mac Mini (Apple Silicon, the intended unattended **production** host; the host login is `<user>@<mac-mini-host>`, kept in the owner's private notes, never in this repo). Anything added here must run on both.

### Verification

**The gate is `npm run verify`.** One command, fail-fast, ten stages: `node --check` over every `.js` under `src/` and `scripts/` (byte-compile), `node --test` over `test/`, then the vendored structure, instruction, doc-refs, static, docs, comment, dead-code and conventions ratchets (`scripts/structure_ratchet.py`, `scripts/instruction_ratchet.py`, `scripts/doc_refs_ratchet.py`, `scripts/static_ratchet.py`, `scripts/docs_ratchet.py`, `scripts/comment_ratchet.py`, `scripts/dead_code_ratchet.py`, `scripts/conventions_ratchet.py`, Python, so a Python 3.11+ must be on `PATH` or in `.venv`). The static ratchet also needs `npx` and `ruff` importable by that Python (`pip install ruff` into `.venv`). It must exit 0 before anything ships.

**The gate never reaches the Realm and can never be an integration test.** Reaching the Realm needs a live Realm, an invited Microsoft account, an interactive device-code sign-in, and a per-machine token cache that by design never leaves the host — and there is only **one connection per Xbox account, ever**, so a test that connected would kick the real bot with `server_id_conflict`. A green gate means *"nothing pure is broken"*, **not** *"the bot can still reach the Realm"*. **Any change to the connect path still needs a manual `npm run spike` against the live Realm**, with the bot account signed out everywhere else. Never report a connect-path change verified on the gate alone.

Decisions recorded so they are not re-litigated (rationale in issue #8):

- **Test runner: `node --test`**, not vitest — zero new dependencies, native ESM, no config. The fleet repos on vitest all test browser-side DOM modules, which doesn't transfer to a headless CLI, and the dependency tree already carries a single-maintainer GitHub fork (BedrockX) pinned by commit plus a `patch-package` hook, so new dev dependencies are real supply-chain surface.
- **No linter, no type checker.** `node --check` already covers the parse-level ground `ruff` covers in Python; `mypy --strict` has no worthwhile equivalent in plain JS. Revisit when `src/` outgrows a handful of modules.
- **No `scripts/verify-before-ship.ps1`.** PowerShell is unrunnable on the Mac Mini, the host that matters most. `/issue-finish` reads the gate command from this file, so `npm run verify` is fully compatible.
- **No CI, deliberately.** CI is advisory in this fleet and its only documented signal beyond the local gate is an e2e suite — which this repo cannot have (the credential / `server_id_conflict` wall above). If it is ever added, follow the fleet's GitHub Actions CI conventions (pinned `windows-2025` runner, Node-24 action majors, one-trigger-per-commit) and write a `## CI expectations` block at that point — not before.
- **Structure ratchet, vendored.** `scripts/structure_ratchet.py` is copied byte-for-byte from project-scaffolding (sha in `.fleet.toml` `[vendored]`; re-vendor through `/propagate-vendored structure_ratchet`, never edit it here). `npm run verify` runs it as stage 3 and fails on any exit other than 0, exit 3 (NOT CONFIRMED) included. It holds files to 1,000 lines, functions to 100 and directories to 40 modules against `.structure-ratchet-baseline.json`, and the root folders to `shape = "node"` plus `extra_roots = ["patches"]`. Baselined functions may not grow; a new module goes where `docs/layout.md` says, and raising a baseline entry needs `--allow-additions`, reviewed.
- **Instruction ratchet, vendored.** `scripts/instruction_ratchet.py` is copied the same way (re-vendor through `/propagate-vendored instruction_ratchet`). `npm run verify` runs it as stage 4 and fails on any exit other than 0, exit 3 included. It runs the fleet prompt audit's deterministic rules over this file and `AGENTS.md` and refuses a count above `.instruction-ratchet-baseline.json`, which is empty today, or a `CLAUDE.md` past 200 lines. Fix a hit by rewording; `--allow-additions` is the reviewed escape hatch.
- **Doc-refs ratchet, vendored.** `scripts/doc_refs_ratchet.py` is copied the same way (re-vendor through `/propagate-vendored doc_refs_ratchet`). `npm run verify` runs it as stage 5 and fails on any exit other than 0, exit 3 included. It fails when `README.md`, `CLAUDE.md` or `docs/**/*.md` names a repo path or relative link that does not exist, beyond `.doc-refs-ratchet-baseline.json`, which is empty today. The BedrockX files the patch edits (under `node_modules/bedrockx`, not tracked here) and the `verify-before-ship.ps1` this file says is absent are named on purpose and listed in `allow_refs` in `.fleet.toml`.
- **Static ratchet, vendored.** `scripts/static_ratchet.py` is copied the same way (re-vendor through `/propagate-vendored static_ratchet`). `npm run verify` runs it as stage 6 and fails on any exit other than 0, exit 3 included, which is what a missing `npx` or `ruff` reports. It fails on a duplicated block (jscpd 5.4.0 through `npx`, the first run downloads it) or a ruff unused-name or bug finding that is not in `.static-ratchet-baseline.json`, which is empty today. Vendored scripts are left out of the scan automatically. Remove a duplicate by extracting a helper; `--allow-additions` is the reviewed escape hatch.
- **Docs ratchet, vendored.** `scripts/docs_ratchet.py` is copied the same way (re-vendor through `/propagate-vendored docs_ratchet`). `npm run verify` runs it as stage 7 and fails on any exit other than 0, exit 3 included. It fails when `README.md` passes 40 KiB, or when `README.md` or `docs/**/*.md` gains an issue-number reference, a dated heading or a changelog heading beyond `.docs-ratchet-baseline.json`, which is empty today. Docs state what is true now; name an upstream pull request by its number in the link text, not as `#N`.
- **Comment ratchet, vendored.** `scripts/comment_ratchet.py` is copied the same way (re-vendor through `/propagate-vendored comment_ratchet`). `npm run verify` runs it as stage 8 and fails on any exit other than 0, exit 3 included. It counts `#N` issue references inside the comments of product code (`src/`, `scripts/`; `*.test.js` is not scanned) and fails when a file's count rises above `.comment-ratchet-baseline.json`, which is empty today. A comment states why the code is the way it is now; the issue and `git log` hold how it got there.
- **Dead-code ratchet, vendored.** `scripts/dead_code_ratchet.py` is copied the same way (re-vendor through `/propagate-vendored dead_code_ratchet`). `npm run verify` runs it as stage 9 and fails on any exit other than 0, exit 3 included. It fails on a Python function, class or method that nothing references and that is not in `.dead-code-ratchet-baseline.json`, which is empty today. It parses Python only and this repo's code is JavaScript, so it guards a Python helper added later and does not see dead JS.
- **Conventions ratchet, vendored.** `scripts/conventions_ratchet.py` is copied the same way (re-vendor through `/propagate-vendored conventions_ratchet`). `npm run verify` runs it as stage 10 and fails on any exit other than 0, exit 3 included. It holds tracked Python to the `no-window` rule (a `subprocess` spawn passes `creationflags=`) and the `no-drive-path` rule (no drive-letter path literal) against `.conventions-ratchet-baseline.json`, which is empty today. `logging-not-print`, `secret-compare` and `git-wrapper` are off, with the reasons in `.fleet.toml`. It reads Python only, so like the dead-code stage it guards a Python helper added later. A call that must break a rule carries a reasoned `# <rule>-exempt: <reason>` marker.
- **No packet-serialization round-trip tests.** False confidence: the `category: 'message_only'` bug round-tripped through the protocol definition *perfectly* and still made the server drop the connection ~16 s later. The real failure modes here are server-side semantics only a live connection reveals.

### Restart recipe: a foreground CLI, **not** a tray

`npm run spike` is long-lived (it supervises and reconnects, #7) but is still a **foreground process with no service port, no tray, and no `/api/version` endpoint**. The scaffold's tray lifecycle — `tray.bat --restart`, orphan-proof port reclaim by PID, the named-mutex guard — does **not** apply and must not be hand-rolled here. There is no port to reclaim.

To restart: stop it with **Ctrl-C** (or `kill <pid>`, where the PID is in `.secrets/bot.lock`) and start it again. Never a blanket `node`/`taskkill` sweep — that would take down unrelated Node processes on the machine.

The single-instance lock makes this safe: a second start refuses immediately and names the holder rather than fighting it for the one available Xbox session, and a stale lock from a hard kill is reclaimed automatically. **Wait ~30s between stopping and restarting** — the server holds the old session, and a faster restart gets `server_id_conflict` (the supervisor handles this correctly, it just costs a backoff cycle).
